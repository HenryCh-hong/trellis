# Privacy and data handling

Student data and application data are sensitive. This documents what is
implemented, not what is aspired to.

## No third-party passwords, anywhere

Trellis holds no Handshake credential, no SUNet password, no Duo code. There is
no field to enter one and no table to store one. The browser extension has no
password input and no `cookies` permission.

Handshake is reached only through the student's own already-authenticated tab,
on their click. Trellis never automates SSO or two-step, never replays a session,
and never touches a Cloudflare or CAPTCHA challenge.

## Secrets at rest

`app/core/security.py` provides Fernet encryption for at-rest secrets, with the
key in a `0600` file outside the repo tree. The scope is deliberately small:
because no third-party passwords exist, the only secrets are things like an
optional Shortcuts webhook token.

## Resumes

- Stored under `apps/api/storage/resumes/`, **outside any static or web-served
  directory**. There is no URL that serves them directly.
- Reachable only through `GET /api/resumes/{id}/file`, which looks the row up by
  id and re-checks that the resolved path is inside the storage directory.
- The on-disk filename is a UUID generated by the server. User input never
  reaches the path, so a crafted filename cannot traverse out.
- Written `0600`.
- The original bytes are never modified. Parsed text is a separate copy.

## Nothing is submitted silently

- `GET /api/applications/{id}/plan` returns exactly what would be submitted,
  what is deliberately withheld and why, and where you must take over.
- Approval is bound to `payload_hash`, a SHA-256 of that exact payload. Editing
  any answer clears `approved_at`, and approving with a stale hash returns
  **409**.
- There is no code path that submits without a matching approval. Assisted apply
  opens the page and hands control back; the student presses submit.

## Sensitive questions are never answered for you

Work authorisation, race/ethnicity, gender, disability, veteran status, criminal
history, age, and self-identification are detected by
`app/services/applications.py::sensitivity_of` and are **always**
`needs_user_input=True`, `answer=None`, `source=USER`.

The model is never asked to draft one. The profile is never used to prefill one —
even when the profile contains the answer. Work authorisation is deliberately
absent from `known_profile_fields()`, the list assisted apply may reuse. Reuse
requires the student to tick `reuse_approved` per answer, defaulting off.

GPA is only reused when the student switches on "use my GPA in applications".

## Logging

`AgentRun.summary` records provider, model, latency and status. Application
answers are never written to it, and the answer routes do not log request bodies.

## Deletion

`DELETE /api/account` removes the user and everything cascading from them —
profile, skills, interests, coursework, experiences, resumes, applications,
answers, events, reminders — and unlinks the resume files from disk. The
harvested public research corpus is not personal data and is left in place.

The UI puts this behind a type-to-confirm input.

## Least privilege

The extension requests `activeTab`, `scripting`, `storage`, and host permissions
scoped to `https://*.joinhandshake.com/*` — not `<all_urls>`. No background page,
no remote code, no cookie access. Extraction is user-initiated and visible.

Server-side fetching identifies itself with a real UA and contact address,
honours `robots.txt`, rate-limits per host, caps response size, and sends no
cookies or credentials. It is never pointed at a page behind anyone's login.
